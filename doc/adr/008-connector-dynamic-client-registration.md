# 008. Connectors register OAuth clients through dynamic client registration only

Status: proposed

The MCP authorization spec allows three ways for a client to register: preregistration, client-id metadata documents (CIMD) and dynamic client registration (DCR, RFC 7591). A review of provider docs, source and metadata on 2026-11-17 found the paths below. The review registered no client. "Yes" shows a protocol path; consent acceptance tests still decide admission.

| Provider   | Hosted HTTPS callback                                                | DCR and CIMD              | Finding and source                                                                                                                                                                                                                                                                                                     |
| ---------- | -------------------------------------------------------------------- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tumpel     | Yes; registration requires HTTPS and excludes fragments and userinfo | DCR yes, CIMD absent      | [Registration handler](../../packages/control-plane/src/index.ts), [metadata](../../packages/control-plane/src/oauth.ts); public S256 client, rotating refresh                                                                                                                                                         |
| Recall     | Yes; `usableRedirect` accepts HTTPS                                  | DCR yes, CIMD absent      | [Pinned OAuth source](https://github.com/mvhenten/recall/blob/1f7fabe50cd935f781ee4a48957a82e18c28f223/src/oauth.ts); server-to-server calls omit the browser `Origin`; Access guards consent only                                                                                                                     |
| GitHub MCP | Yes, with a registered app callback                                  | No documented DCR or CIMD | [Host guide](https://github.com/github/github-mcp-server/blob/main/docs/host-integration.md), [S256 support](https://github.blog/changelog/2025-07-14-pkce-support-for-oauth-and-github-app-authentication/); app preregistration exists, but generic discovery and exchange stay unproven                             |
| Linear     | Yes, inferred from hosted Claude support and OAuth metadata          | Advertises both           | [Docs](https://linear.app/docs/mcp), [metadata](https://mcp.linear.app/.well-known/oauth-authorization-server); S256 and refresh; workspace admission can restrict access                                                                                                                                              |
| Sentry     | Yes; exact registered non-loopback redirects                         | Both                      | [Worker](https://github.com/getsentry/sentry-mcp/blob/main/packages/mcp-cloudflare/src/server/index.ts), [provider validator](https://github.com/cloudflare/workers-oauth-provider/blob/v0.10.3/src/oauth-provider.ts), [metadata](https://mcp.sentry.dev/.well-known/oauth-authorization-server); S256 and refresh    |
| Context7   | Yes, through Clerk, subject to client admission                      | Advertises both           | OAuth uses `/mcp/oauth` ([docs](https://context7.com/docs/howto/oauth)); [metadata](https://mcp.context7.com/.well-known/oauth-authorization-server) names Clerk; [CIMD rules](https://clerk.com/docs/guides/configure/auth-strategies/oauth/client-id-metadata-documents) accept HTTPS callbacks. API keys use `/mcp` |

The Worker registers a public client through DCR on each authorization. A server that advertises no registration endpoint fails `ConnectorRegistrationUnsupported`. GitHub MCP connects with a static PAT.

Tumpel and Recall offer DCR only, and Linear, Sentry and Context7 advertise it. DCR alone covers every OAuth provider in the table. The choice drops preregistration, CIMD, a published client metadata document and stored client secrets. It costs every OAuth server that lacks DCR. A later ADR adds CIMD when a provider the tenant needs requires it.
